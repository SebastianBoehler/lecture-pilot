# Learning evidence, reviewed variants and multilingual teaching

Approved in chat: implement the five directions from the project brainstorm.

## Product contract

The professor approves learning goals and constraints. Reviewed teaching and
assessment variants implement those goals. Learner evidence records the exact
task, support and revision; it distinguishes supported, independent and delayed
performance. A visible canvas learning loop connects the current goal, specific
missing evidence, support, a fresh independent check and later review.

Independent attempts use a focused canvas surface with explanations, notes,
sources and tutor help put away. Requesting help explicitly records support
before it is displayed. It does not claim to detect outside assistance. A task
that has received task-specific help is never reused as fresh independent evidence.
When a reviewed bank is exhausted, expose the actual limitation and continue
supported study without inventing an unreviewed assessment or claiming mastery.

## Reviewed task content

Prepare a small bank of source-backed task variants during practice design.
Keep stable goal identity and distinct task identities. Include bounded numerical
consistency assertions where appropriate; no arbitrary code execution. Exact
wording, variants and assertions are part of the implementation/publication
revision. Professor-fixed targets remain protected. Legacy approved design and
published learning-map hashes remain readable without silent mutation.

Existing baseline, independent-exit and delayed-transfer tasks remain usable.
Newly generated implementations provide additional parallel tasks for fresh checks
after task-specific support. Native structured generation, semantic review and
backend source validation cover the bank; hidden assessments never enter canvas
teaching authoring prompts. Reviewer agreement is not semantic proof.

## Language variants

First supported explanation languages: German and English. Canonical published
assessment language remains explicit and unchanged. Translation variants adapt
teaching text while retaining formulas, code, references, goal/task identities and
all assessment blocks. No automatic translated assessment equivalence is claimed.

A professor generates a shared explanation variant, previews it and explicitly
publishes its exact digest against the unchanged canonical publication. Learners
choose only current published variants; sources/assessment remain authoritative.
A canonical publication change makes older explanation variants unavailable until
reviewed again. Personalized notes remain learner-owned.

## Professor review and performance

Show deterministic changes to goals/tasks since the previous saved implementation
and any recorded repair reason, without trusting a model to describe its own diff.
Keep final draft approval exact. Documentation must describe current ownership.

Profile repeated published reads. If repeated parsing is material, reuse validated
compiled snapshots within bounded memory while detecting changed files and keeping
per-request authorization, private overlays and publication checks outside the
shared cache. Report measured scope and do not infer total tutoring capacity.

## Engineering and verification

Use existing FastAPI/Pydantic AI/React boundaries, no new framework or services.
New code files stay below 300 lines. Preserve private source/workspace storage.
Test contracts first, then targeted integration and relevant broad suites.
Exercise professor preparation/publication and learner support/fresh-check/reload
in the local browser, including German/English and light/dark presentation.
No production deployment, research participation, efficacy claim or silent approval
migration follows from this implementation.
