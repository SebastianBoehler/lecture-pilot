# Designing LecturePilot for independent learning

**Scope** · Student lesson and tutor workflow. Evidence checked 26 November 2026. This targeted review follows primary experiments across memory, instruction, attention, reading, and interface design. It extends the existing [learning evidence audit](2026-09-25-lecturepilot-evidence-audit.md), [neuroscience review](2026-09-06-neuroscience-learning-evidence.md), and [display media review](2026-09-06-display-media-learning-evidence.md).

## What to optimize

A student should be able to explain or apply the course idea on a new task days later, with the lesson and tutor closed. That is the learning outcome. Time to find the right passage, time to finish practice, and use of hints explain where the interface helps or costs effort. Measure those separately. In a randomized physics study, students learned more during active instruction even as they felt they learned less. [Deslauriers et al.](https://doi.org/10.1073/pnas.1821936116)

Working memory is limited. An interface should remove the effort of locating a formula, finding a relevant example, or deciphering a button. Preserve the effort of generating an answer, deciding when a rule applies, and explaining why. The first part is an interface design problem. The second part is a learning activity.

## Lesson layout and language

- **Reading.** Keep the canvas as the primary surface. Pair the explanation with its equation or figure. Place examples and their rationales in document order. Keep optional sources, tool traces, and details behind controls the student can open. Support keyboard navigation and zoom without hiding the content that matters.
- **Practice.** Make the task and its section explicit. In independent practice, hide answers and hints until the appropriate action. Offer equivalent ways to enter an answer where the learning outcome permits it. Use paper or ink when the task needs drawing or notation.
- **Feedback.** Let the learner reopen their submitted work in the feedback surface. State what reasoning is sound, identify one consequential issue, and give one next action. Keep a saved correction attached to its section.
- **Review.** Offer a reviewed changed case at a later session. Judge the unaided answer with a fixed rubric. An assisted turn, a saved note, and a passing independent assessment represent different evidence.
- **Visual system.** Use text and a visible indicator for the current action or state. Check 4.5:1 contrast for normal text and 3:1 for large text and applicable non-text controls. Verify keyboard focus, reduced motion, text enlargement, and reflow. Allow local horizontal overflow for content that needs two dimensions, such as a long equation or table. These checks establish usability and access. [WCAG 2.2](https://www.w3.org/TR/WCAG22/)

## First implementation

The recall controls display the published section name before activation and expose it as their accessible description. The feedback dialog lets the learner reopen the exact submitted image beside the feedback. The image stays in the open dialog and this uses the original tutor response. When a tutor result specifies a valid passage, the canvas scrolls there once and keeps a stable visual cue. A section target remains available when its passage is missing.

These changes reduce navigation ambiguity and make comparison available. The evidence for those mechanisms comes from other systems and materials. The product code and regression tests establish the implemented behavior. Learning gains require a separate evaluation.

## Smallest informative tests

**Find and correct the right work.** Use a short math derivation and a diagram task, each with an existing published section and a plausible neighboring distractor. Compare the prior flow and the named-section flow with a fixed objective, camera or iPad workflow, and tutor reply. Counterbalance task and version order in a small usability pilot. Record wrong-section starts, whether the student locates the relevant step, and whether the correction addresses it according to a predefined rubric. Run keyboard and narrow-screen cases, and check English and German wording. A small pilot can surface failures and estimate task variability.

**Check whether co-located feedback improves transfer.** Fix the section label in both conditions. Randomly assign access to the submitted page during feedback, with the same instructional material, practice time, feedback, and review opportunity. Use a pretest for prior knowledge and a new unaided task after seven days. Predefine a meaningful improvement and choose a sample from pilot variance and expected return rate. Score answers blind to assignment. Analyze participants as the independent units and report attendance, attrition, and interval estimates. Track quality of corrections and time as secondary measures. Report any change to the delayed test or grading rubric before scoring.

**Compare other directions independently.** Test a worked-step handoff before changing graphics where novices cannot start. Test delayed recall before investing in richer media where students can perform with hints and forget later. Test familiar examples with the same underlying principle and comparable surface complexity. Reconsider a design if it increases wrong attempts, disadvantages a device or access mode, or changes only satisfaction. A palette-only experiment is a low priority unless an accessibility check or specific diagram task exposes a problem.

No learner study has run for this pass. A later efficacy study needs a predeclared protocol and approval appropriate to the participating course. The code change adds no experiment assignments or collection of learner answers.
